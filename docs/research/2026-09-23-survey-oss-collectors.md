# OSS survey: org-wide Claude Code (and multi-agent) session telemetry, as of 2026-09-23

Scope: open-source tools that pull Claude Code (or multiple coding agents') usage/session data from **many developers' machines into one central store** and analyze it. Excludes Anthropic's own claude.ai Team/Enterprise analytics dashboard, AWS CloudWatch Coding Agent Insights, and GitHub Copilot's official metrics API/dashboard: all real and relevant to the underlying need, but proprietary/vendor products, not OSS. Every repo below was fetched and verified (metadata + README) on 2026-09-23, none were taken from search snippets alone.

### Session-replay tools (single-machine cluster, not central, noted but not tabled individually)
Several projects convert one JSONL session into a shareable/replayable artifact: [harrylettering/claude-trace-replay](https://github.com/harrylettering/claude-trace-replay), [es617/claude-replay](https://github.com/es617/claude-replay), [constripacity/Claude-Replay](https://github.com/constripacity/Claude-Replay), [tanghong123/claude-replay](https://github.com/tanghong123/claude-replay), [NickCirv/claude-session-replay](https://github.com/NickCirv/claude-session-replay). All operate on one session/one machine and have no central aggregation across developers.

## Where the ask is not met by OSS
- **LLM-judge over full transcripts, run centrally across an org**: not found. `claudedashboard`'s "Coach" is the closest analog, but it judges activity metrics (it never captures prompt/response text). `claudit` explicitly refuses to add this. No project ingests many developers' raw JSONL centrally and runs a judge model over the transcript text itself.
- **Per-skill usage at org scale**: only `claudedashboard` (telemetry pack plus `skills:scan` catalog) and `cc-analytics` (via PostHog) genuinely track this across developers; everything else is single-machine or doesn't break out skills.
- **"Where sessions fail" analysis org-wide**: `claudit` (tool error rate) and `claude-code-otel` (success rates) are the two with this at a central, multi-developer level; most others are single-machine.
