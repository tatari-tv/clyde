**Anthropic net picture:** four distinct, non-overlapping surfaces (OTel, two flavors of Analytics dashboard, two Analytics APIs, plus Compliance API for content). Skill-level and MCP-server-level breakdowns exist only in the OTel stream (per-event, self-hosted) and in the Claude Enterprise Analytics API's connector/skill adoption endpoint (org-wide, not session-level). Nothing from Anthropic natively gives "which skills/MCP servers by which person in which session" as a single queryable table. That gap is exactly what the third-party vendors below are selling.

## Where org-wide, skill-level Claude Code telemetry actually stands

- Nobody, not Anthropic, not any third party, currently ships a single managed product that gives "which skill/MCP server, by which named person, in which session, at what cost" without the customer standing up their own OTel collector (or having Anthropic's local Compliance API access, which is audit-scoped, not analytics-scoped).
- The OTel export (Anthropic's own, and Cursor's structurally similar one) is the only place skill/tool/MCP-call-level granularity exists per session; every managed SaaS product (DX, LinearB, Jellyfish, Swarmia, Faros, minware) is built on top of the coarser daily per-user Analytics API, not the event-level OTel stream, because the OTel stream requires the customer to run infrastructure.
- GitHub Copilot's Metrics API is ahead of Anthropic specifically on MCP-server-adoption-as-a-named-field (available via API, org/enterprise granularity); Anthropic's equivalent (connector adoption) lives only in the separate Claude Enterprise Analytics API, not the Claude Code Analytics API, and is org-level not session-level.
- MintMCP is the one vendor whose architecture (MCP gateway in front of all agents) puts it in a structurally different position: it can see MCP-server and skill-level calls directly, across tools, rather than depending on what each vendor's export chooses to expose.
