How consumers read it

clyde fetches this URL at runtime and caches the result, so a data refresh reaches consumers within about 24 hours with no crate bump and no re-pin. That split is the point: fast-changing data (this JSON) never forces a rebuild of the slow-changing library that consumes it.

Each binary also compiles in a baseline copy of this feed, and it never serves anything older than that baseline: a cached or fetched feed whose data_version is behind the embedded one loses, and the embedded data is used instead. So a stale or unreachable feed degrades to "as good as the binary you installed", never to worse.

How it is produced

pricing.json is a generated artifact, not a hand-maintained file. A daily cron (.github/workflows/refresh-pricing.yml, 06:17 UTC) runs pricing/bin/update, which scrapes Anthropic's published pricing page and opens a PR only when the data actually changed. Merging that PR to main deploys this page and the JSON beside it (.github/workflows/pages.yml).

bin/update refuses to ship questionable data rather than publishing it:

  • Two independent parsers (one awk, one Python) read the same input, and their outputs are compared for semantic equality (5 and 5.0 agree). Any real disagreement is a hard stop, with a diff naming the models that differ.
  • Delisted models carry forward at their last known rates rather than vanishing, so a model disappearing upstream never silently becomes unpriceable. The cross-check above is what still catches a parser accidentally dropping a row that is genuinely still listed.
  • Two regression checks against the previous published file: no rate may move by more than 5x, and every rate must sit within absolute bounds of $0.001 to $1000 per MTok.

New model launches are not hands-off

Worth knowing before trusting a brand-new model's row to appear on its own. Model keys are derived by slugifying the row label on the upstream pricing table. When a model ships with date-tiered introductory pricing it occupies two rows ("… through August 31, 2026" and "… starting September 1, 2026"), and the parser emits one broken key per tier instead of one clean model id.

The bare opus / sonnet / haiku aliases are human-authored policy in data/normalization.json and are never repointed automatically. So a launch needs a person to pick the canonical id, choose the correct tier, fold the broken rows into it, and repoint the alias. Until that happens the daily cron keeps regenerating the broken keys.

Schema

The crate's major version is locked to schema_version: a v2 tag means schema 2. min_library_version is the crate version that ships the current schema, so a consumer too old to understand this feed can detect that and fall back to its embedded baseline instead of misreading the file.
